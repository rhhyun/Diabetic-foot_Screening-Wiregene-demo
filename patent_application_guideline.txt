당뇨발 위험평가 및 관리 프로그램 특허출원 검토 가이드
변리사 전달용 기술 설명 초안
작성일: 2026-07-07

주의:
이 문서는 특허 법률의견이 아니라, 변리사가 명세서와 청구항 방향을 잡기 위한 기술 설명 초안입니다.
실제 출원 가능성, 신규성, 진보성, 공개예외, 의료기기/소프트웨어 특허 적격성은 변리사가 최종 검토해야 합니다.

1. 발명 후보 명칭

문진, 임상 측정 및 센서 특징 융합 기반 당뇨발 위험 예측 및 관리 시스템 및 방법

대체 명칭:
- 당뇨발 조기 선별을 위한 다중 입력 융합 위험도 산출 시스템
- 환자 문진, 의료진 평가 및 센서 시계열 데이터를 이용한 당뇨발 추적관리 방법

2. 해결하려는 문제

기존 당뇨발 관리는 환자 문진, 의료진 진찰, 혈관/신경 검사, 온도/압력/영상 센서 결과가 분리되어 관리되는 경우가 많습니다.
그 결과, 조기 위험 신호가 누락되거나, 센서 변화가 임상 위험도와 직접 연결되지 않거나, 추적 우선순위가 늦게 결정될 수 있습니다.
본 프로그램은 환자 문진에서 시작해 임상 측정값과 센서 feature를 같은 연구 record에 순차적으로 결합하고,
당뇨발 위험 등급, 주요 예측 endpoint, 우선 확인 포인트, 권장 다음 조치를 한 화면에서 산출하는 것을 목표로 합니다.

3. 현재 구현된 핵심 구성

- 환자 문진 모듈:
  성별, 연령, 당뇨 기간, 치료 형태, HbA1c, 과거 궤양/절단/시술, 신경병증 증상, 허혈 증상, 현재 발 상태,
  발 관리 습관, 신발/보행 습관, 동반질환, 사진/센서 연구 참여 의향을 단계적으로 입력합니다.

- 임상 측정 모듈:
  10 g monofilament 이상, 맥박 결손 수, TBI, toe pressure, TcPO2, 발 변형, 활동성 상처, 발적, 굳은살,
  부종, 감염 의심, IWGDF confirmed risk class를 같은 record에 추가합니다.

- 센서 및 시계열 feature 모듈:
  기준선 대비 증상/온도/압력/관류/활동량/순응도/영상 변화, 광학 관류 feature, 열 hotspot feature,
  영상 변화 점수, 족저압/보행 feature, 섬유/온도/압력 배열 feature를 직접 입력하거나 CSV로 반영합니다.

- 규칙 기반 융합 및 예측 모듈:
  문진 점수, 임상 측정값, 센서 feature, rule-fusion signal을 결합해 다음 endpoint를 산출합니다.
  1) 6개월 신규 궤양
  2) 6개월 재발 궤양
  3) 지속성 hotspot
  4) 상처 악화
  5) 혈관 평가 의뢰 필요
  6) 압력 분산 실패
  7) 고위험군 전환 가능성

- 관리자/대시보드 모듈:
  record 목록, 위험도 분포, 데이터 완성도, 예측 근거, 긴급 확인 포인트, 권장 다음 조치,
  JSON DB 가져오기/내보내기를 제공합니다.

- 저장 구조:
  동일한 화면을 유지하면서, API와 중앙 DB가 있으면 원격 저장을 우선 사용하고,
  없으면 브라우저 localStorage로 fallback하는 구조입니다.

4. 변리사에게 설명할 발명 포인트

- 하나의 연구 record가 환자 문진 -> 관리자 검토 -> 임상 입력 -> 센서/CSV 입력 순서로 점진적으로 보강됩니다.
- 문진 기반 정적 위험점수와 임상 측정값, 센서 feature, rule-fusion signal을 결합해 endpoint별 위험도를 따로 계산합니다.
- 단순 총점이 아니라, 신규 궤양, 재발 궤양, hotspot 지속, 상처 악화, 혈관 평가 의뢰, 압력 분산 실패, 고위험군 전환을 분리해 표시합니다.
- 데이터 완성도에 따라 현재 예측 단계가 문진 중심, 임상 보강, 센서 보강 단계인지 구분하고, 다음에 필요한 측정 입력을 권장합니다.
- 센서 CSV field를 내부 feature group으로 매핑하여 수기 입력과 파일 입력을 같은 예측 엔진에 연결합니다.
- 위험도 결과와 함께 근거 문장, 우선 확인 항목, 권장 조치를 출력해 의료진의 추적관리 판단을 돕습니다.

5. 청구항 검토 후보

변리사 검토 요청 청구항 유형:

- 방법 청구항:
  환자 문진 데이터를 수신하고, 정적 위험 feature를 생성하고, 임상 측정값 및 센서 feature를 같은 record에 결합하고,
  rule-fusion flag를 생성한 뒤, endpoint별 위험도와 권장 조치를 출력하는 컴퓨터 구현 방법.

- 시스템 청구항:
  문진 입력부, 임상 측정 입력부, 센서 feature 입력부, record 정규화부, rule-fusion 처리부,
  endpoint별 위험도 산출부, 관리자 대시보드 출력부를 포함하는 시스템.

- 컴퓨터 판독 가능 매체 또는 컴퓨터프로그램 청구항:
  위 방법을 수행하도록 하는 명령을 저장한 매체 또는 프로그램.

- 선택적 종속항 후보:
  1) 온도 hotspot 지속일, 양측 온도차, 족저압, 관류지표, 영상 상처점수 중 하나 이상을 이용하는 구성
  2) IWGDF confirmed risk class와 문진 기반 risk class 차이를 이용해 고위험군 전환 가능성을 산출하는 구성
  3) 데이터 완성도에 따라 추가 임상 또는 센서 측정을 권장하는 구성
  4) CSV field명을 내부 센서 feature group으로 정규화하는 구성
  5) 중앙 DB와 local fallback을 모두 지원하는 연구/시연 데이터 저장 구성

6. 변리사에게 함께 제공하면 좋은 자료

- 현재 GitHub 저장소 URL 및 최초 공개일/업데이트 이력
- 화면 캡처: 환자 문진, 관리자 대시보드, 임상 입력, 센서 입력, 예측 결과
- 주요 소스 파일: models.mjs, app.mjs, admin.mjs, clinician.mjs, sensor.mjs, record-utils.mjs
- 데이터 구조 표: questionnairePayload, clinicianMeasurements, aiFeatureGroups, ruleFusionSignals, predictionEndpoints
- 예측 로직 요약표: 각 endpoint별 입력 feature, threshold, 가중치, 출력 문구
- 실제 적용 예정 센서 종류와 자체 개발 여부
- 이미 외부 공개된 자료, 데모 URL, 발표자료, GitHub 공개일

7. 변리사에게 꼭 확인할 질문

- 현재 공개된 GitHub/데모가 신규성에 영향을 주는지, 공개예외 또는 우선권 전략이 필요한지
- 한국 단독 출원, PCT, 미국/일본/유럽 병행 출원 중 어떤 전략이 적절한지
- 소프트웨어 발명으로서 방법, 시스템, 매체, 컴퓨터프로그램 청구항을 어느 범위까지 가져갈 수 있는지
- IWGDF 등 기존 진료지침과 비교했을 때 신규한 기술적 특징을 어디에 둘지
- 의료진의 진단행위 자체가 아니라, 데이터 처리와 위험도 산출/관리 워크플로우로 청구항을 구성하는 것이 적절한지
- 센서 하드웨어가 아직 특정되지 않은 경우, "센서 feature를 수신하는 시스템"으로 넓게 청구할 수 있는지
- 임상데이터 또는 실제 환자데이터 없이 데모 규칙 기반 로직만으로도 우선 출원이 가능한지

9. 내부 결론

본 프로그램의 핵심은 "당뇨발 위험 관리를 위한 다중 입력 record 보강 및 endpoint별 rule-fusion 예측"입니다.
단순 설문 앱이나 단순 센서 기록 앱이 아니라, 문진-임상-센서-시계열 정보를 하나의 record로 융합하고,
위험도와 다음 조치까지 산출하는 컴퓨터 구현 워크플로우로 설명하는 것이 좋습니다.
